코랩으로 선형회귀

센서가 알려주는 건 0~1023이라는 숫자일 뿐, 몇 도인지 몇 센티인지가 아닙니다. 그 숫자를 실제 값으로 바꿔주는 식을 데이터에서 직접 찾아내는 것, 그게 선형회귀입니다.

이 강의를 마치면

  • 선형회귀가 무엇을 하는 것인지 설명할 수 있다
  • 구글 코랩에서 파이썬 코드를 실행할 수 있다
  • 데이터를 그래프로 그리고, 가장 잘 맞는 직선을 구할 수 있다
  • 결정계수 R²로 “얼마나 잘 맞는지” 판단할 수 있다
  • 구한 식을 아두이노 코드에 다시 넣어 센서를 보정할 수 있다

지금까지 연산은 늘 아두이노 안에서, 값이 들어오는 순간 즉석으로 했습니다. 이번에는 데이터를 먼저 모아두고, 컴퓨터에서 한꺼번에 분석합니다. 아두이노 혼자서는 못 하는 일이고, 실제 제품을 만들 때 반드시 거치는 과정입니다.

선형회귀란?

7강에서 자기장 센서를 읽었을 때를 떠올려 봅시다. analogRead()가 604를 돌려줬다면 그건 몇 가우스일까요? 알 수 없습니다. 센서는 그냥 전압을 숫자로 바꿔줄 뿐이니까요.

방법은 하나입니다. 정답을 아는 상황을 몇 번 만들어 놓고, 그때 센서가 뭐라고 하는지 기록하는 것입니다. 온도계로 잰 진짜 온도가 20°C일 때 센서는 145였고, 30°C일 때는 165였다 — 이런 짝을 여러 개 모읍니다. 그 점들 사이로 가장 잘 지나가는 직선을 찾으면, 앞으로는 센서 값만 보고도 온도를 알 수 있습니다.

우리가 찾으려는 것
온도 = a × (센서 값) + b

  a = 기울기 — 센서 값이 1 올라갈 때 온도가 얼마나 오르는지
  b = 절편   — 센서 값이 0일 때의 온도 (계산상의 기준점)

이 a 와 b 를 데이터에서 찾아내는 것이 '선형회귀'입니다.
왜 하필 직선인가

세상 모든 관계가 직선은 아닙니다. 하지만 온도 센서, 거리 센서, 무게 센서처럼 많은 센서가 설계상 직선에 가깝게 만들어져 있습니다. 그리고 직선이 아닌 경우에도, 좁은 구간만 보면 대체로 직선에 가깝습니다. 그래서 가장 먼저 시도해 보는 것이 직선입니다.

가장 잘 맞는 직선이란?

점들이 한 줄로 완벽하게 늘어서 있지는 않습니다. 측정에는 늘 오차가 있으니까요. 그러면 “가장 잘 맞는다”는 걸 어떻게 정할까요?

기준은 이렇습니다. 각 점에서 직선까지의 세로 거리를 재고, 그걸 제곱해서 전부 더합니다. 이 합이 가장 작아지는 직선이 정답입니다. 이 방법을 최소제곱법이라고 합니다.

왜 제곱을 할까

그냥 더하면 위로 벗어난 오차(+)와 아래로 벗어난 오차(−)가 서로 상쇄되어 엉터리 직선도 0에 가까워집니다. 제곱하면 모두 양수가 되어 상쇄되지 않고, 크게 벗어난 점에 더 큰 벌점을 주는 효과도 있습니다.

아래에서 슬라이더로 직선을 직접 움직여 보세요. 주황색 세로선이 오차이고, SSE가 그 오차를 제곱해서 더한 값입니다. SSE를 가장 작게 만들어 보세요.

손으로 찾기는 어렵습니다

직접 해보면 알겠지만, 두 값을 동시에 맞추는 건 꽤 성가십니다. 그런데 이 최적값은 계산으로 한 번에 구할 수 있습니다. 코랩에서는 np.polyfit() 한 줄이면 끝납니다. 지금부터 그걸 해봅시다.

import matplotlib.pyplot as plt

# 아두이노가 읽은 값
raw  = np.array([111, 124, 132, 145, 152, 165, 173, 186])

# 온도계로 잰 실제 온도 (°C)

셀 3 · 직선 구하기

여기가 핵심입니다. 한 줄입니다.

셀 3
a, b = np.polyfit(raw, temp, 1)    # 1 = 1차식, 즉 직선

print("기울기 a =", round(a, 4))
print("절편   b =", round(b, 4))
print()
print("온도 =", round(a, 4), "× raw +", round(b, 4))
출력
기울기 a = 0.478 절편 b = -48.4766 온도 = 0.478 × raw + -48.4766

아까 슬라이더로 찾으려던 그 값입니다. np.polyfit이 최소제곱법을 계산으로 한 번에 풀어준 것입니다. 마지막 인자 1은 “1차식(직선)으로 맞춰라”라는 뜻입니다. 2를 넣으면 포물선이 됩니다.

셀 4 · 그래프에 직선 겹치기

셀 4
line_x = np.linspace(raw.min(), raw.max(), 100)   # x를 100등분
line_y = a * line_x + b                          # 각 x에 대한 직선의 y

plt.figure(figsize=(6, 4))
plt.scatter(raw, temp, color='#c0503c', s=60, zorder=3, label='measured')
plt.plot(line_x, line_y, color='#3c6ea8', lw=2,

점들 사이로 직선이 지나가는 게 보이면 성공입니다. 위쪽으로 벗어난 점과 아래쪽으로 벗어난 점이 비슷하게 섞여 있어야 잘 맞은 것입니다. 한쪽으로만 몰려 있다면 직선이 아닌 관계일 가능성이 큽니다.

셀 5 · 얼마나 잘 맞을까

눈으로 보는 것 말고 숫자로 판단하는 기준도 필요합니다. 가장 많이 쓰는 것이 결정계수 R²입니다. 1에 가까울수록 잘 맞는 것이고, 0에 가까우면 직선으로 설명이 안 된다는 뜻입니다.

셀 5
pred  = a * raw + b        # 직선이 예측한 온도
error = temp - pred        # 실제와의 차이 (잔차)

sse = np.sum(error ** 2)                  # 오차 제곱합
sst = np.sum((temp - temp.mean()) ** 2)   # 전체가 흩어진 정도
r2  = 1 - sse / sst                       # 결정계수

print("잔차:", np.round(error, 2))
print("오차 제곱합 SSE =", round(sse, 2))
print("결정계수 R²     =", round(r2, 4))
출력
잔차: [ 0.42 -0.79 0.39 -0.83 0.83 -0.39 0.79 -0.42] 오차 제곱합 SSE = 3.27 결정계수 R² = 0.9969

R²가 0.997입니다. 온도 변화의 99.7%를 이 직선이 설명한다는 뜻이고, 센서 보정으로는 아주 좋은 결과입니다. 잔차도 ±0.8°C 안쪽에서 부호가 번갈아 나타납니다 — 규칙 없이 섞여 있다는 건 좋은 신호입니다.

R² 값해석
0.95 이상아주 잘 맞음. 그대로 쓰면 됩니다.
0.8 ~ 0.95쓸 만하지만 오차가 있습니다. 측정을 더 늘려보세요.
0.8 미만직선이 아닐 가능성이 큽니다. 그래프를 다시 보세요. 곡선이거나, 측정이 잘못됐거나, 관계가 없는 것입니다.
R²가 높다고 항상 옳은 건 아닙니다

데이터가 2~3개뿐이면 R²는 거의 1이 나옵니다. 점 두 개는 무조건 직선 위에 있으니까요. 최소 6~8개 이상 모으고, 측정 범위도 넓게 잡아야 믿을 수 있는 결과가 나옵니다.

셀 6 · 예측하기

이제 측정하지 않았던 값도 온도로 바꿀 수 있습니다. 이게 회귀의 목적입니다.

셀 6
def to_temp(value):
    return a * value + b

for v in [120, 158, 178]:
    print(v, "→", round(to_temp(v), 1), "°C")
출력
120 → 8.9 °C 158 → 27.0 °C 178 → 36.6 °C
측정한 범위 밖은 믿지 마세요

우리는 111부터 186까지만 측정했습니다. to_temp(900)도 숫자를 내놓긴 하지만 근거가 전혀 없는 값입니다. 회귀는 본 적 있는 범위 안에서만 믿을 수 있습니다.

scikit-learn으로도 해보기

np.polyfit이 가장 간단하지만, 머신러닝 쪽에서는 scikit-learn을 더 많이 씁니다. 결과는 똑같습니다. 앞으로 다른 모델을 배울 때 쓰는 방식이 전부 이 모양이라 익혀둘 만합니다.

셀 7 (선택)
from sklearn.linear_model import LinearRegression

X = raw.reshape(-1, 1)     # sklearn은 입력을 '세로로 세운' 모양으로 받습니다

model = LinearRegression()
model.fit(X, temp)         # 학습 — 여기서 a, b 를 찾습니다

print("기울기 a =", round(model.coef_[0], 4))
print("절편   b =", round(model.intercept_, 4))
print("R²       =", round(model.score(X, temp), 4))

print("raw 158 →", round(model.predict([[158]])[0], 1), "°C")
출력
기울기 a = 0.478 절편 b = -48.4766 R² = 0.9969 raw 158 → 27.0 °C
단계하는 일
model = ...()모델을 하나 만듭니다. (아직 아무것도 모르는 상태)
model.fit(X, y)학습 — 데이터를 보고 가장 잘 맞는 값을 찾습니다.
model.predict(...)예측 — 새 값을 넣어 결과를 얻습니다.
model.score(X, y)얼마나 잘 맞는지 (R²)
이 만들기 → fit → predict 순서는 scikit-learn의 거의 모든 모델에서 똑같습니다.
reshape(-1, 1)은 왜 필요할까

scikit-learn은 “입력 특징이 여러 개일 수도 있다”고 전제합니다. 그래서 데이터를 가로 한 줄이 아니라 세로 한 칸으로 세워서 줘야 합니다. -1은 “개수는 알아서 맞춰라”라는 뜻입니다. 안 하면 오류가 나니 그냥 규칙으로 외우면 됩니다.

아두이노에 다시 넣기

여기까지가 진짜 목적입니다. 코랩에서 구한 a와 b를 아두이노 코드에 옮겨 적으면, 이제 아두이노가 스스로 온도를 말합니다.

CalibratedSensor.ino
// 코랩에서 구한 값을 그대로 옮겨 적습니다.
const float A = 0.4780;
const float B = -48.4766;

const int SENSOR = A0;

void setup() {
  Serial.begin(9600);
}

void loop() {
  int raw = analogRead(SENSOR);

  // 여기가 코랩에서 찾은 식입니다
  float temp = A * raw + B;

  Serial.print("raw ");
  Serial.print(raw);
  Serial.print("  →  ");
  Serial.print(temp, 1);      // 소수점 1자리까지
  Serial.println(" C");

  delay(500);
}
이게 왜 중요한가

아두이노는 polyfit 같은 계산을 하기엔 너무 작습니다. 하지만 곱셈 한 번과 덧셈 한 번은 얼마든지 할 수 있죠. 무거운 계산은 컴퓨터가 미리 해두고, 아두이노는 그 결과만 쓰는 것 — 이게 실제 제품에서 센서를 다루는 방식입니다.

float와 소수점 출력

소수를 담으려면 int가 아니라 float를 씁니다. 그리고 Serial.print(temp, 1)의 두 번째 인자는 소수점 자릿수입니다. 안 쓰면 기본 2자리로 나옵니다.

const int SENSOR = A0;

void setup() {
  Serial.begin(9600);
}

void loop() {
  Serial.println(analogRead(SENSOR));
  delay(1000);      // 1초에 하나씩
}

시리얼 모니터를 열고, 조건을 하나 정할 때마다 실제 값을 따로 기록합니다. (온도계를 옆에 두고 읽거나, 자를 대고 거리를 재거나.) 숫자가 안정되면 그 값을 적어두세요.

2. 코랩에 옮기기

가장 간단한 방법은 그냥 옮겨 적는 것입니다. 데이터가 10~20개면 이게 제일 빠릅니다.

직접 입력
raw  = np.array([112, 128, 140, 151, 166, 174])   # 내가 읽은 센서 값
temp = np.array([  6,  12,  18,  23,  30,  34])   # 내가 잰 실제 값

데이터가 많다면 CSV 파일로 만들어 올리는 방법도 있습니다.

CSV 파일 올리기
from google.colab import files
import pandas as pd

uploaded = files.upload()          # 실행하면 파일 선택 창이 뜹니다

df = pd.read_csv('data.csv')       # 파일 이름을 실제 이름으로
print(df.head())                   # 앞부분 몇 줄 확인

raw  = df['raw'].values            # 열 이름으로 꺼내기
temp = df['temp'].values

CSV는 엑셀이나 메모장으로 만들면 됩니다. 첫 줄에 열 이름(raw,temp)을 쓰고, 그 아래로 111,5 처럼 쉼표로 구분해 적으면 끝입니다.

도전과제

① 점 하나를 망가뜨려 보기

셀 1에서 temp의 값 하나를 엉뚱하게 바꿔보세요. (예: 25를 90으로) 그리고 셀 3·4·5를 다시 실행합니다. 직선이 어떻게 끌려가는지, R²가 얼마나 떨어지는지 확인하세요. 이상한 데이터 하나가 결과 전체를 망가뜨릴 수 있다는 걸 눈으로 보는 게 목적입니다.

② 데이터를 줄여보기

데이터를 앞의 3개만 남기고 다시 해보세요. R²는 오히려 더 높게 나올 겁니다. 그런데 이 결과를 더 믿을 수 있을까요? 왜 그런지 생각해 보세요.

③ 직선이 아닌 데이터에 직선 맞추기

아래 데이터로 셀 2~5를 그대로 해보세요. 그래프와 R²가 무슨 이야기를 하는지 보세요.

데이터 보기
곡선 데이터
# 자석과의 거리(cm)에 따른 자기장 세기 — 직선이 아닙니다
raw  = np.array([  1,   2,   3,   4,   5,   6,   7,   8])
temp = np.array([980, 420, 210, 130,  85,  62,  48,  40])

7강에서 다룬 자기장이 실제로 이런 모양입니다. 거리가 멀어질수록 급격히 약해지죠. 이런 데이터에 직선을 맞추면 R²가 낮게 나오고, 그래프의 점들이 직선 아래위로 규칙적으로 휘어 있습니다. 이럴 때는 np.polyfit(raw, temp, 2)처럼 차수를 올리거나, 로그를 취하는 방법을 씁니다.

④ 나만의 센서 보정하기 (심화)

가진 센서로 데이터를 직접 10개 이상 모아 회귀를 돌리고, 구한 식을 아두이노에 넣어 실제 단위로 출력되는 장치를 완성하세요. 밝기 센서면 “어두움/밝음”, 거리 센서면 “cm”가 시리얼 모니터에 찍히게 만드는 것이 목표입니다.
