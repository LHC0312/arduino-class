06강 · 종합 실습

신호등 만들기

지금까지 배운 것을 전부 씁니다. LED 세 개를 정해진 순서와 시간으로 켜면 그게 바로 신호등입니다. 마지막에는 버튼과 부저를 붙여 입력 → 연산 → 출력이 모두 들어간 장치를 완성합니다.

이 강의를 마치면

  • LED 세 개 회로를 GND 레일을 써서 정리할 수 있다
  • 반복되는 코드를 함수로 묶고, 배열로 여러 핀을 한꺼번에 다룰 수 있다
  • delay()의 한계를 알고 millis()로 바꿀 수 있다
  • 상태(state)라는 개념으로 버튼에 반응하는 장치를 만들 수 있다

동작 정리하기

코드를 쓰기 전에 말로 먼저 정리합니다. 이 습관이 있으면 코드가 훨씬 빨리 나옵니다. 우리가 만들 신호등은 이렇게 동작합니다.

단계켜지는 등시간의미
1초록5초통행
2노랑2초정지 준비
3빨강5초정지
→ 다시 1번으로 돌아가 무한 반복
중요한 규칙

한 번에 하나만 켜져 있어야 합니다. 새 등을 켜기 전에 나머지를 반드시 끄세요. 이걸 빼먹으면 시간이 지날수록 등이 하나씩 늘어나 결국 셋 다 켜집니다.

회로 만들기

3강에서 만든 회로를 세 번 반복하면 됩니다. 다만 GND 점퍼선을 세 개나 쓰긴 아까우니, 이번에는 브레드보드의 (−) 전원 레일을 씁니다. 아두이노 GND를 레일에 한 번만 연결해 두면 레일 전체가 GND가 되어 LED 세 개가 나눠 쓸 수 있습니다.

시작 전

USB 케이블을 뽑으세요. 배선이 다 끝난 뒤에 다시 꽂습니다.

배선표

LED핀연결 경로
빨강1010번 → 220Ω → LED(+) → LED(−) → (−) 레일
노랑99번 → 220Ω → LED(+) → LED(−) → (−) 레일
초록88번 → 220Ω → LED(+) → LED(−) → (−) 레일
공통아두이노 GND → 브레드보드 (−) 레일 (점퍼선 1개)
배선을 마쳤으면 확인하세요
  • LED 세 개의 긴 다리가 모두 저항 쪽을 향하고 있는가
  • LED 세 개의 짧은 다리가 모두 같은 (−) 레일에 꽂혀 있는가
  • GND 점퍼선이 (−) 레일(파란 줄)에 꽂혀 있는가 — 빨간 줄에 꽂으면 동작하지 않습니다
  • 부품의 두 다리가 같은 세로줄에 꽂혀 있지 않은가

동작 미리보기

업로드하기 전에, 우리가 만들 신호등이 어떻게 동작할지 먼저 봅시다. 실행을 누르면 아래에 지금 실행 중인 코드가 함께 표시됩니다.

속도를 올리면 delay()의 값이 그만큼 작아진 것과 같습니다. 실제 코드에서는 5000, 2000 같은 숫자를 직접 바꾸면 됩니다.

1단계 · 배운 대로 그대로 쓰기

먼저 아무 기교 없이, 알고 있는 명령만으로 만들어 봅시다. 이 코드는 정상 동작합니다.

TrafficLight_1.ino
const int RED    = 10;
const int YELLOW = 9;
const int GREEN  = 8;

void setup() {
  pinMode(RED, OUTPUT);
  pinMode(YELLOW, OUTPUT);
  pinMode(GREEN, OUTPUT);
}

void loop() {
  // 1) 초록 5초
  digitalWrite(RED, LOW);
  digitalWrite(YELLOW, LOW);
  digitalWrite(GREEN, HIGH);
  delay(5000);

  // 2) 노랑 2초
  digitalWrite(RED, LOW);
  digitalWrite(YELLOW, HIGH);
  digitalWrite(GREEN, LOW);
  delay(2000);

  // 3) 빨강 5초
  digitalWrite(RED, HIGH);
  digitalWrite(YELLOW, LOW);
  digitalWrite(GREEN, LOW);
  delay(5000);
}

업로드해서 동작을 확인하세요. 잘 되나요? 그런데 코드를 다시 봅시다. digitalWrite가 아홉 줄이나 있고, 거의 똑같은 모양이 세 번 반복됩니다. 만약 신호등을 4색으로 바꾸거나 시간을 조정하려면 여러 곳을 고쳐야 하고, 그러다 한 줄만 빠뜨려도 등 두 개가 동시에 켜집니다.

프로그래밍의 기본 원칙

같은 코드가 두 번 이상 반복되면, 묶을 때가 된 것입니다. 아래에서 이 코드를 단계적으로 줄여 나가겠습니다. 동작은 똑같지만 훨씬 읽기 쉬워집니다.

2단계 · 함수로 정리

“전부 끄기”와 “하나만 켜고 기다리기”를 각각 함수로 만듭니다. 함수는 여러 줄짜리 동작에 이름을 붙이는 것입니다.

TrafficLight_2.ino
const int RED    = 10;
const int YELLOW = 9;
const int GREEN  = 8;

void setup() {
  pinMode(RED, OUTPUT);
  pinMode(YELLOW, OUTPUT);
  pinMode(GREEN, OUTPUT);
}

// 세 개를 모두 끕니다.
void allOff() {
  digitalWrite(RED, LOW);
  digitalWrite(YELLOW, LOW);
  digitalWrite(GREEN, LOW);
}

// 지정한 등 하나만 켜고, 주어진 시간만큼 유지합니다.
void light(int pin, int ms) {
  allOff();
  digitalWrite(pin, HIGH);
  delay(ms);
}

void loop() {
  light(GREEN,  5000);
  light(YELLOW, 2000);
  light(RED,    5000);
}

loop()가 세 줄로 줄었습니다. 게다가 읽는 순간 동작이 이해됩니다. “초록 5초, 노랑 2초, 빨강 5초.” 시간을 바꾸고 싶으면 그 숫자만 고치면 되고, light() 안에서 항상 allOff()를 먼저 부르기 때문에 두 개가 동시에 켜지는 실수가 원천적으로 불가능합니다.

문법뜻
void allOff() { … }돌려주는 값이 없는(void) 함수 allOff를 만듭니다. allOff(); 라고 부르면 중괄호 안이 실행됩니다.
void light(int pin, int ms)값 두 개를 받아서 동작하는 함수. light(RED, 5000)으로 부르면 pin에는 10이, ms에는 5000이 들어갑니다.

3단계 · 초록불 깜빡임 추가

실제 신호등은 초록이 꺼지기 직전에 몇 번 깜빡여 “곧 바뀝니다”라고 알려 줍니다. 이것도 함수로 만들면 한 줄로 끝납니다.

TrafficLight_3.ino
// 위쪽 상수·setup·allOff·light 는 2단계와 같습니다.

// 지정한 등을 times 번 깜빡입니다.
void blinkPin(int pin, int times, int ms) {
  for (int i = 0; i < times; i++) {
    digitalWrite(pin, HIGH);
    delay(ms);
    digitalWrite(pin, LOW);
    delay(ms);
  }
}

void loop() {
  light(GREEN, 4000);        // 초록 4초
  allOff();
  blinkPin(GREEN, 3, 300);   // 초록 3번 깜빡 (0.3초 간격)
  light(YELLOW, 2000);       // 노랑 2초
  light(RED,    5000);       // 빨강 5초
}

for (int i = 0; i < times; i++) 는 “i를 0부터 times−1까지 늘리며 반복”이라는 뜻입니다. blinkPin(GREEN, 3, 300)은 초록을 3번 깜빡이고, blinkPin(GREEN, 10, 100)은 10번 빠르게 깜빡입니다. 함수 하나로 모든 깜빡임 패턴을 만들 수 있게 된 것입니다.

4단계 · delay()의 한계와 millis()

여기까지 코드는 잘 동작하지만 큰 약점이 하나 있습니다. delay()가 실행되는 동안 아두이노는 아무것도 하지 못합니다. delay(5000)이면 5초 동안 완전히 멈춰 있습니다.

그래서 지금 코드에 보행자 버튼을 붙이면, 학생이 버튼을 눌러도 최대 5초 동안 반응이 없습니다. 센서를 읽거나 부저를 울리는 것도 마찬가지입니다.

해결 방법 — 멈추지 말고 시계를 보기

millis()는 보드가 켜진 뒤 지금까지 흐른 시간(밀리초)을 알려 줍니다. 멈춰서 기다리는 대신, loop()를 계속 돌면서 “충분히 지났나?”를 확인하는 방식으로 바꿉니다. 라면을 끓일 때 3분간 눈 감고 기다리는 대신, 다른 일을 하면서 가끔 시계를 보는 것과 같습니다.

TrafficLight_4.ino
const int RED    = 10;
const int YELLOW = 9;
const int GREEN  = 8;

// 순서와 시간을 배열에 나란히 적어 둡니다.
const int  pins[3]      = {GREEN, YELLOW, RED};
const long durations[3] = {5000,  2000,   5000};

int step = 0;                    // 지금 몇 번째 단계인지
unsigned long lastChange = 0;    // 마지막으로 바뀐 시각

void setup() {
  for (int i = 0; i < 3; i++) {
    pinMode(pins[i], OUTPUT);
    digitalWrite(pins[i], LOW);
  }
  digitalWrite(pins[step], HIGH);   // 첫 단계 켜기
  lastChange = millis();
}

void loop() {
  unsigned long now = millis();

  // 현재 단계의 시간이 다 지났으면 다음 단계로
  if (now - lastChange >= durations[step]) {
    digitalWrite(pins[step], LOW);    // 지금 켜진 것 끄고
    step = (step + 1) % 3;            // 다음 번호로 (2 다음은 0)
    digitalWrite(pins[step], HIGH);   // 다음 것 켜기
    lastChange = now;
  }

  // loop()가 멈추지 않으므로, 여기에 버튼 확인 같은 일을
  // 얼마든지 추가해도 신호등은 계속 정확히 돌아갑니다.
}
문법뜻
int pins[3] = {8, 9, 10};배열 — 값 여러 개를 한 이름으로 묶습니다. 번호는 0부터 셉니다.
pins[0]첫 번째 값(8). pins[2]는 세 번째 값(10)입니다.
millis()보드가 켜진 뒤 지난 시간(ms). 약 50일 뒤에 0으로 돌아갑니다.
unsigned long아주 큰 양의 정수를 담는 그릇. millis() 값은 반드시 이 형으로 받아야 합니다.
(step + 1) % 33으로 나눈 나머지. 0 → 1 → 2 → 0 → … 처럼 돌고 돌게 만듭니다.

도전과제 · 버튼으로 제어하는 신호등

지금까지의 신호등은 아무도 없어도 혼자 계속 돌아갑니다. 실제 횡단보도 신호등은 그렇지 않죠. 평소에는 차가 다니도록 초록을 유지하다가, 사람이 버튼을 누르면 그때 신호를 바꿉니다. 5강에서 배운 버튼 입력과 4강의 부저 출력을 여기에 붙입니다.

동작 정의

지금 상태넘어가는 조건다음 상태
초록 (기본)버튼이 눌림노랑
노랑2초 경과빨강
빨강5초 경과초록 (기본으로 복귀)

이렇게 “지금 어떤 상태인가”와 “언제 다음으로 넘어가는가”만 정하면 동작 전체가 정의됩니다. 이런 방식을 상태 기계(state machine)라고 부르는데, 엘리베이터·자판기·게임 캐릭터까지 거의 모든 제어 장치가 이 구조로 만들어집니다.

먼저 눌러 보기

아래 시뮬레이터의 버튼을 눌러 보세요. 초록에서 대기하다가 노랑 2초 → 빨강 5초를 거쳐 다시 초록으로 돌아옵니다. 노랑이나 빨강일 때는 버튼을 눌러도 반응하지 않습니다. 이미 신호가 바뀌는 중이기 때문입니다.

추가 배선

앞의 신호등 회로는 그대로 두고, 버튼과 부저만 더 붙입니다.

부품핀연결
택트 스위치2한쪽 다리 → 2번 핀, 대각선 반대쪽 다리 → (−) 레일
INPUT_PULLUP을 쓰므로 저항이 필요 없습니다
부저7(+) → 7번 핀, (−) → (−) 레일
이미 만들어 둔 (−) 레일 덕분에

버튼과 부저의 GND도 같은 레일에 꽂기만 하면 끝입니다. GND 점퍼선을 새로 뽑을 필요가 없습니다. 이게 전원 레일을 쓰는 이유입니다.

코드

CrossingLight.ino
const int RED    = 10;
const int YELLOW = 9;
const int GREEN  = 8;
const int BUTTON = 2;    // 입력
const int BUZZER = 7;    // 출력

// 상태에 이름을 붙여 둡니다. 숫자 0,1,2 보다 읽기 쉽습니다.
const int WAIT_GREEN = 0;   // 초록 — 버튼을 기다리는 중
const int TO_YELLOW  = 1;   // 노랑 — 2초
const int TO_RED     = 2;   // 빨강 — 5초

const long YELLOW_MS = 2000;
const long RED_MS    = 5000;
const long BEEP_GAP  = 700;   // 빨강일 때 삑 소리 간격

int state = WAIT_GREEN;
unsigned long stateStart = 0;   // 지금 상태가 시작된 시각
unsigned long lastBeep   = 0;

void allOff() {
  digitalWrite(RED, LOW);
  digitalWrite(YELLOW, LOW);
  digitalWrite(GREEN, LOW);
}

void setLight(int pin) {
  allOff();
  digitalWrite(pin, HIGH);
}

void setup() {
  pinMode(RED, OUTPUT);
  pinMode(YELLOW, OUTPUT);
  pinMode(GREEN, OUTPUT);
  pinMode(BUZZER, OUTPUT);
  pinMode(BUTTON, INPUT_PULLUP);   // 저항 없이 버튼 연결

  setLight(GREEN);                 // 기본은 초록
  state = WAIT_GREEN;
  stateStart = millis();
}

void loop() {
  unsigned long now = millis();

  if (state == WAIT_GREEN) {
    // 버튼이 눌릴 때까지 초록을 유지합니다.
    // INPUT_PULLUP 이므로 '눌림 = LOW' 입니다.
    if (digitalRead(BUTTON) == LOW) {
      tone(BUZZER, 1568, 80);      // 접수음 '띵'
      setLight(YELLOW);
      state = TO_YELLOW;
      stateStart = now;
    }
  }

  else if (state == TO_YELLOW) {
    if (now - stateStart >= YELLOW_MS) {
      setLight(RED);
      state = TO_RED;
      stateStart = now;
      lastBeep = now;
    }
  }

  else if (state == TO_RED) {
    // 건너는 동안 일정 간격으로 삑 소리
    if (now - lastBeep >= BEEP_GAP) {
      tone(BUZZER, 1200, 90);
      lastBeep = now;
    }

    if (now - stateStart >= RED_MS) {
      setLight(GREEN);
      state = WAIT_GREEN;
      stateStart = now;
    }
  }
}
여기서 tone()의 세 번째 인자가 빛을 발합니다

tone(BUZZER, 1200, 90)은 기다리지 않고 바로 다음 줄로 넘어갑니다. 소리를 내면서도 loop()는 계속 돌기 때문에 신호등의 시간이 밀리지 않습니다. 여기에 delay(90)을 썼다면 그만큼 신호가 늦어집니다.

코드가 그림과 어떻게 대응되는지

안 될 때

증상원인
버튼을 눌러도 아무 반응이 없음== HIGH로 비교하고 있지 않은지 확인하세요. INPUT_PULLUP에서는 눌림이 LOW입니다.
버튼을 안 눌렀는데 계속 바뀜버튼의 반대쪽 다리가 GND가 아니라 5V에 연결되어 있습니다. 또는 같은 쌍의 두 다리를 써서 항상 이어진 상태입니다.
노랑이 순식간에 지나감stateStart = now; 누락. 위 경고를 확인하세요.
빨강에서 안 돌아옴RED_MS와 비교하는 부분에서 stateStart 대신 lastBeep을 쓰고 있지 않은지 확인하세요.
소리가 안 남부저 (+)가 7번 핀에 맞게 꽂혔는지, pinMode(BUZZER, OUTPUT)이 있는지 확인하세요.

① 시간 바꾸기

우리 동네 횡단보도를 관찰해서 실제 시간에 맞춰 보세요. 버튼을 누른 뒤 몇 초 만에 바뀌던가요?

② 빨강 → 초록 사이에 준비 신호

일부 나라의 신호등은 빨강에서 초록으로 바뀌기 직전에 빨강과 노랑을 동시에 켭니다. 상태를 하나 더 추가해 보세요.

힌트 보기

TO_GREEN_READY = 3 을 만들고, TO_RED가 끝나면 이 상태로 넘어가게 합니다. 이 상태에서는 setLight() 대신 직접 두 개를 켭니다.

추가할 상태
else if (state == TO_GREEN_READY) {
  allOff();
  digitalWrite(RED, HIGH);
  digitalWrite(YELLOW, HIGH);    // 두 개 동시에

  if (now - stateStart >= 1000) {
    setLight(GREEN);
    state = WAIT_GREEN;
    stateStart = now;
  }
}

③ 빨강이 끝나갈 때 빨리 삑삑거리기

남은 시간이 2초 이하로 줄면 삑 소리 간격을 700ms에서 250ms로 줄여 보세요. 실제 횡단보도처럼 “서둘러 건너세요”가 됩니다. 힌트: long gap = (now - stateStart > RED_MS - 2000) ? 250 : 700;

④ 버튼을 미리 눌러 두기 (심화)

지금은 노랑·빨강일 때 버튼을 누르면 그냥 무시됩니다. “눌렸다”는 사실만 기억해 두었다가 다음 초록에서 곧바로 신호를 바꾸도록 만들어 보세요. 힌트: bool requested = false; 변수를 하나 두고, 어느 상태에서든 버튼이 눌리면 true로 바꿉니다.

⑤ 양방향 교차로 (심화)

LED 세 개를 더 준비해서 마주 보는 두 방향의 신호등을 만들어 보세요. 한쪽이 초록일 때 다른 쪽은 반드시 빨강이어야 합니다. 동시에 초록이 되는 순간이 있으면 안 됩니다.
