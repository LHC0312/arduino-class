버튼 입력

지금까지는 아두이노가 말하기만 했습니다. 이제 듣는 법을 배웁니다. 버튼 하나를 붙이는 순간, 정해진 대로만 움직이던 장치가 사람에게 반응하기 시작합니다.

이 강의를 마치면

  • 택트 스위치의 어느 다리끼리 연결되어 있는지 안다
  • 플로팅 문제가 무엇이고 왜 저항이 필요한지 설명할 수 있다
  • digitalRead()로 버튼 상태를 읽고 if로 판단할 수 있다
  • 누를 때마다 켜지고 꺼지는 토글을 만들 수 있다

택트 스위치의 구조

키트에 들어 있는 작은 네모 버튼을 택트 스위치라고 합니다. 다리가 4개인데, 여기에 함정이 하나 있습니다. 4개가 모두 따로가 아니라, 2개씩 짝지어 안에서 이미 연결되어 있습니다.

가장 흔한 실수

이미 연결되어 있는 같은 쪽 두 다리에 선을 연결하면, 버튼을 누르든 말든 항상 이어진 상태가 됩니다. 이걸 피하려면 대각선으로 마주 보는 두 다리를 쓰세요. 어느 쌍이 어느 쌍인지 몰라도 대각선은 반드시 다른 쌍입니다.

브레드보드에 꽂는 방향

택트 스위치는 가운데 홈을 걸치도록 꽂아야 합니다. 그래야 왼쪽 두 다리와 오른쪽 두 다리가 서로 다른 세로줄에 들어갑니다. 한쪽에만 꽂으면 다리가 같은 줄에 몰려 합선됩니다. 잘 안 들어가면 방향을 90도 돌려 보세요.

플로팅 — 저항이 필요한 이유

버튼을 그냥 “핀 ↔ 5V”로만 연결하면 어떻게 될까요? 누르면 5V가 들어와 HIGH가 되는 건 맞습니다. 그런데 누르지 않았을 때가 문제입니다. 그 핀은 아무 데도 연결되지 않은 채 공중에 떠 있게 됩니다. 이걸 플로팅(floating)이라고 합니다.

플로팅 상태의 핀은 주변 전자기 노이즈를 안테나처럼 주워 담아 HIGH와 LOW를 제멋대로 오갑니다. 손을 가까이 대기만 해도 값이 바뀝니다. 그래서 버튼이 눌리지 않았을 때 확실히 한쪽 값이 되도록 붙잡아 주는 저항이 필요합니다.

수업에서는 이렇게

먼저 풀다운 저항으로 “누르면 HIGH”를 직접 만들어 원리를 이해하고, 그다음 INPUT_PULLUP으로 바꿔 부품 없이 같은 일을 하는 것을 확인합니다. 아래 시뮬레이터로 두 방식의 값 차이를 먼저 비교해 보세요.

연결 방식

같은 동작인데 읽히는 값이 정반대인 것에 주목하세요. 그래서 INPUT_PULLUP을 쓸 때는 조건문이 == LOW가 됩니다. 이걸 놓치면 “버튼을 안 눌렀는데 LED가 켜져 있어요”가 됩니다.

회로 만들기 — 풀다운 방식

시작 전

USB 케이블을 뽑으세요. 배선이 끝난 뒤에 다시 꽂습니다.

배선표

순서연결부품
1택트 스위치를 브레드보드 가운데 홈에 걸쳐서 꽂기택트 스위치
2아두이노 5V → 버튼 위쪽 다리 줄점퍼선 (빨강)
3아두이노 2번 핀 → 버튼 아래쪽 다리 줄점퍼선 (노랑)
4버튼 아래쪽 다리 줄 → (−) 레일저항 10kΩ
5아두이노 GND → (−) 레일점퍼선 (검정)
6아두이노 13번 → 220Ω → LED(+) → LED(−) → (−) 레일LED, 220Ω
10kΩ 저항 색띠

갈색 · 검정 · 주황 · 금색입니다. 갈(1) 검(0) 주(×1000) → 10 × 1000 = 10,000Ω = 10kΩ. 220Ω(빨빨갈금)과 헷갈리지 않게 세 번째 띠를 잘 보세요.

값 읽어보기

회로가 제대로 됐는지 확인하는 가장 확실한 방법은 값을 눈으로 보는 것입니다. 2강의 시리얼 모니터를 씁니다.

ReadButton.ino
const int BUTTON = 2;

void setup() {
  pinMode(BUTTON, INPUT);   // 이 핀으로 '읽겠다'고 선언
  Serial.begin(9600);
}

void loop() {
  int state = digitalRead(BUTTON);   // 0 또는 1이 들어옵니다
  Serial.println(state);
  delay(100);
}

업로드하고 시리얼 모니터를 열면 이렇게 나와야 합니다.

누르지 않았는데 0과 1이 마구 섞여 나온다면

플로팅입니다. 10kΩ 저항이 빠졌거나, 저항이 GND가 아닌 다른 곳에 연결되어 있습니다. 위 배선표 4·5번을 다시 확인하세요.

명령뜻

digitalRead(핀)그 핀의 상태를 읽어 HIGH(1) 또는 LOW(0)를 돌려줍니다.
int state = …읽은 값을 state라는 상자에 담아 둡니다. 나중에 비교할 때 씁니다.

누르면 불 켜기

이제 읽은 값으로 판단해서 LED를 켭니다. 입력 → 연산 → 출력이 한 화면에 모두 들어옵니다.

ButtonLed.ino
const int BUTTON = 2;    // 입력
const int LED    = 13;   // 출력

void setup() {
  pinMode(BUTTON, INPUT);
  pinMode(LED, OUTPUT);
}

void loop() {
  int state = digitalRead(BUTTON);   // ① 입력: 버튼 읽기

  if (state == HIGH) {               // ② 연산: 눌렸는가?
    digitalWrite(LED, HIGH);         // ③ 출력: 켜기
  } else {
    digitalWrite(LED, LOW);          //    안 눌렸으면 끄기
  }
}
= 와 == 는 다릅니다

= 는 넣어라(대입), == 는 같은가?(비교)입니다. if (state = HIGH)라고 쓰면 오류 없이 넘어가지만 항상 참이 되어 LED가 계속 켜져 있습니다. 찾기 아주 어려운 버그이니 조건문에서는 반드시 ==를 쓰세요.

더 짧게 쓰기

digitalRead()의 결과를 그대로 digitalWrite()에 넘길 수도 있습니다. 둘 다 HIGH/LOW를 쓰기 때문입니다.

한 줄 버전
void loop() {
  digitalWrite(LED, digitalRead(BUTTON));
}

동작은 똑같습니다. 다만 “읽어서, 판단하고, 쓴다”는 흐름이 잘 안 보이므로 처음에는 if 버전으로 이해하는 편이 낫습니다.

INPUT_PULLUP으로 바꾸기

이번엔 10kΩ 저항을 빼고 같은 동작을 만들어 봅시다. 아두이노 안에는 이미 풀업 저항이 들어 있어서, 코드로 켜기만 하면 됩니다.

바꿀 것내용
회로10kΩ 저항을 제거합니다. 버튼의 한쪽 다리는 2번 핀, 반대쪽 다리는 GND로 연결합니다. (5V 선은 필요 없습니다.)
코드pinMode(BUTTON, INPUT) → pinMode(BUTTON, INPUT_PULLUP)
조건if (state == HIGH) → if (state == LOW) — 값이 뒤집힙니다
ButtonLed_Pullup.ino
const int BUTTON = 2;
const int LED    = 13;

void setup() {
  // 보드 안의 풀업 저항을 켭니다. 외부 저항이 필요 없습니다.
  pinMode(BUTTON, INPUT_PULLUP);
  pinMode(LED, OUTPUT);
}

void loop() {
  // 주의: 눌렸을 때가 LOW 입니다 (평소에는 HIGH)
  if (digitalRead(BUTTON) == LOW) {
    digitalWrite(LED, HIGH);
  } else {
    digitalWrite(LED, LOW);
  }
}
왜 값이 뒤집힐까

풀업 저항은 핀을 평소에 5V 쪽으로 끌어올려 둡니다. 그래서 아무것도 안 하면 HIGH입니다. 버튼을 누르면 핀이 GND와 직접 이어지면서 0V, 즉 LOW로 끌어내려집니다. 저항보다 직접 연결이 훨씬 “센” 길이기 때문입니다.

누를 때마다 켜고 끄기 — 토글

지금 코드는 누르고 있는 동안만 켜집니다. 방 전등처럼 한 번 누르면 켜지고, 다시 누르면 꺼지게 하려면 두 가지가 더 필요합니다.

  1. 지금 켜져 있는지 기억하기

    변수 하나에 상태를 저장해 둡니다. loop() 밖에 선언해야 값이 유지됩니다.

  2. “눌린 순간”만 잡아내기

    loop()는 1초에 수만 번 돌기 때문에, 한 번 눌러도 “눌림”이 수천 번 감지됩니다. 직전 값과 지금 값이 달라진 순간만 잡아야 합니다.

Toggle.ino
const int BUTTON = 2;
const int LED    = 13;

bool ledOn = false;        // 지금 LED가 켜져 있는가
int  lastState = HIGH;     // 직전에 읽은 버튼 값
unsigned long lastChange = 0;

void setup() {
  pinMode(BUTTON, INPUT_PULLUP);
  pinMode(LED, OUTPUT);
}

void loop() {
  int state = digitalRead(BUTTON);

  // 값이 방금 바뀌었고, 마지막 변화로부터 50ms가 지났을 때만 인정
  if (state != lastState && millis() - lastChange > 50) {
    lastChange = millis();

    if (state == LOW) {          // HIGH → LOW, 즉 '눌린 순간'
      ledOn = !ledOn;            // 켜져 있으면 끄고, 꺼져 있으면 켜기
      digitalWrite(LED, ledOn ? HIGH : LOW);
    }
    lastState = state;
  }
}
문법뜻
bool참(true) 또는 거짓(false) 둘 중 하나만 담는 그릇입니다.
!ledOn반대로 뒤집기. true면 false가, false면 true가 됩니다.
state != lastState!= 는 “같지 않다”. 값이 방금 바뀌었다는 뜻입니다.
ledOn ? HIGH : LOWledOn이 참이면 HIGH, 거짓이면 LOW. if/else를 한 줄로 줄인 것입니다.

채터링 — 왜 50ms를 기다릴까

버튼은 금속 조각 두 개가 부딪히는 기계 장치입니다. 누르는 순간 접점이 수 밀리초 동안 미세하게 튕기면서 붙었다 떨어졌다를 여러 번 반복합니다. 이것을 채터링(bouncing)이라고 합니다. 사람은 한 번 눌렀지만 아두이노는 대여섯 번 눌린 것으로 읽습니다. 그래서 토글이 제멋대로 동작하죠.

위 코드의 millis() - lastChange > 50이 이걸 막아 줍니다. 한 번 변화를 인정하면 50ms 동안은 더 이상 받아들이지 않는 것입니다. 이 처리를 디바운스(debounce)라고 합니다.

직접 확인해 보기

&& millis() - lastChange > 50 부분을 지우고 업로드해 보세요. 버튼을 눌렀을 때 LED가 제멋대로 켜지거나 꺼지는 것을 볼 수 있습니다. 이게 채터링입니다.
